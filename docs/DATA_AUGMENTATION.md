# 学習時の Data Augmentation

対象: `scripts/07_train.py`  
作成日: 2026年10月2日

## 概要

Data Augmentation（データ拡張）は、学習データにランダムな変換を加え、撮影方向や照明などの違いにモデルが対応できるようにする処理です。本プログラムでは、動画から取り出した区間（segment）の画像列と骨格列に対して、データを読み込む際に適用します。元の画像・骨格ファイルやデータベースを書き換えることはありません。同じ区間でも、学習中に読み込むたびに変換が再抽選されます。

集中度予測モデルと授業状況分類モデルの両方で、同じ学習用 Dataset を使うため、以下の変換が適用されます。集中度と授業状況の正解ラベルは変更しません。

## モード別の適用内容

| 処理 | image | skeleton | fusion |
| --- | --- | --- | --- |
| 左右反転 | 画像 | 骨格 | 画像と骨格を同期して反転 |
| 明るさ・コントラスト・彩度・色相の変換 | 画像 | 適用なし | 画像 |
| グレースケール化 | 画像 | 適用なし | 画像 |
| ランダム切り抜き・サイズ変更 | 画像 | 適用なし | 画像 |

## 1. 左右反転

学習時、各区間に対して 50% の確率で左右反転を行います。区間内の全フレームに同じ判断を適用するため、途中のフレームだけ反転することはありません。時間の順序は維持します。

画像では、水平方向に画像を反転します。骨格では、中心化・スケール正規化済みの x 座標の符号を反転し、左右の関節を交換します。交換対象は目、耳、肩、肘、手首、股関節、膝、足首で、鼻の関節番号は維持します。関節を交換する際は、y 座標と検出信頼度も対応する関節と一緒に移動します。骨格の左右反転は COCO-17 形式の17関節を前提としています。

fusion モードでは、画像と骨格に同じ反転判断を適用し、両者の左右方向を揃えます。通常の左側カメラと、右側カメラの撮影方向の違いに対応することを目的としています。ただし、左右反転だけでは、カメラ位置の違いによる遠近感や身体の隠れ方まで再現できません。

## 2. 明るさと色の変換（Color Jitter）

image と fusion モードの学習画像に、以下の範囲でランダムな変換を加えます。

| 項目 | 設定値 | 実際に抽選する範囲 | 目的 |
| --- | --- | --- | --- |
| 明るさ | brightness=0.25 | 係数 0.75～1.25 | 教室の明暗の違いへの対応 |
| コントラスト | contrast=0.25 | 係数 0.75～1.25 | 画像の濃淡の違いへの対応 |
| 彩度 | saturation=0.35 | 係数 0.65～1.35 | 色の鮮やかさの違いへの対応 |
| 色相 | hue=0.03 | 色相のずれ -0.03～+0.03 | 照明やカメラによる色味の違いへの対応 |

明るさ・コントラスト・彩度の係数は、1.0 が変化なしを表します。色相の値は torchvision の色相変換の単位であり、度数ではありません。

変換係数と適用順序は区間ごとに一度だけ抽選し、全フレームで共有します。これにより、augmentation によってフレームごとに明るさや色が急変することを防ぎます。元の動画に含まれる照明変化はそのまま残ります。

明るさの変換は画素値に対する処理です。暗所で生じるノイズや動体ぶれ、強い逆光による情報の欠落をすべて再現するものではありません。

## 3. グレースケール化

image と fusion モードでは、各区間を 25% の確率でグレースケール化します。区間内の全フレームで適用の有無を揃えます。モデルへの入力形式を維持するため、グレースケール化後も3チャンネルで扱います。

服や背景の色への依存を減らし、形状や姿勢などの情報も利用できるようにすることを目的としています。

## 4. ランダム切り抜きとサイズ変更（RandomResizedCrop）

image と fusion モードでは、画像からランダムに領域を切り抜き、モデルの入力サイズへ変更します。

- 切り抜き面積の指定範囲: 入力画像面積の 80～100%（scale=(0.8, 1.0)）。
- 縦横比の指定範囲: 3/4～4/3（torchvision の既定値）。
- 出力サイズ: img_size × img_size。CLI の既定値は 224 × 224。

人物の位置や写る範囲の小さな違いへの対応を目的としています。領域は指定範囲で抽選され、切り抜き候補が成立しない場合は torchvision の中央切り抜きへのフォールバックが使われます。

2026年10月8日の修正後は、切り抜き領域を区間ごとに一度だけ抽選します。人物クロップのサイズがフレーム間で変わる場合も、相対的な位置と大きさを共有します。静止画像の列にランダムな見かけの動きを作らないための修正です。fusion モードの骨格は人物内で中心化・スケール正規化した特徴であり、画像切り抜きに合わせた座標変換は行いません。

## 5. 時系列フレームの選択

フレーム選択は sample_strategy により異なります。

- uniform（既定値）: 区間全体から等間隔で T フレームを選びます。ランダムな時間方向の拡張はありません。
- random: 学習時、元の区間に T フレーム以上ある場合、開始位置をランダムに選んで連続する T フレームを取り出します。区間内の異なる時間部分を学習に使用できます。

検証時は random を指定していても等間隔の選択を使います。T フレーム未満の場合は、末尾のフレームを繰り返して長さを揃えます。時間の逆転、速度変更、骨格へのランダムノイズ追加は実装していません。

## Augmentation と通常の前処理の違い

以下は入力形式を揃えるための通常の前処理であり、ランダムなデータ拡張とは区別します。

- image_roi の設定に応じた画像領域の切り出し。
- 画像の Tensor 化と、RGB の mean=[0.485, 0.456, 0.406]、std=[0.229, 0.224, 0.225] による正規化。
- 骨格の中心化とスケール正規化。信頼度 0.2 以上の関節を基準として計算します。

画像の学習時の処理順は、領域切り出し → 左右反転 → 区間で共通のランダム切り抜き・サイズ変更 → 色変換 → グレースケール化 → Tensor 化 → 正規化です。骨格は正規化後に左右反転します。

## 検証時の扱い

検証用 Dataset には、左右反転、色変換、グレースケール化、ランダム切り抜きを適用しません。画像は Resize(img_size + 32) と CenterCrop(img_size) で入力サイズに揃え、その後 Tensor 化と正規化を行います。骨格も通常の正規化のみ行います。

## 利用方法と効果の確認

### 常時グレースケールでの学習

`--grayscale` を指定すると、image/fusionモードの全画像を常時グレースケールにして学習します。骨格は従来どおり使用し、ResNetへの入力形状を保つため画像は同じ輝度の3チャンネルとして扱います。既存モデルと、オプションを指定しない学習は従来のRGBのままです。

- `--grayscale --augmentation none`: 常時グレースケール、ランダム変換なし。
- `--grayscale --augmentation standard`: 常時グレースケールに、区間で同期した左右反転・ランダム切り抜き・明るさ／コントラスト変換を適用。彩度・色相の変換と25%確率のグレースケール抽選は使いません。
- `--image_roi upper_body` と併用すると上半身のグレースケール画像を使用します。fusionでは骨格も併用し、画像のみの条件を試す場合は `--mode image` を指定します。

grayscale設定はチェックポイントのcfgに保存され、ラベル付きDB評価、オフライン動画推論、リアルタイム推論へ自動的に反映します。検証・推論も常時グレースケールですが、ランダム変換は適用しません。評価時に `--grayscale` を再指定する必要はありません。

例（シチュエーション自動判定の分類器も学習、集中度学習の正解状況混合比は既定の0.5）:

```powershell
python scripts/07_train.py `
  --data_roots datasets/20260227_unnan_nishi_5-1_1,datasets/20260227_unnan_nishi_5-1_2,datasets/20260311_unnan_nishi_5-1_1,datasets/20260313_unnan_nishi_5-1_1_a `
  --label_source individual --raters tadano `
  --mode fusion --temporal transformer `
  --lr 1e-4 --fusion_image_scale 0.5 --include_pilot_post `
  --T 10 --sample_strategy uniform --image_roi upper_body `
  --situation_epochs 10 --grayscale --augmentation standard `
  --save_name models/pre_test_fusion_transformer_gray_aug.pt
```

集中度学習時も自動推定の状況だけを使用する比較では、さらに `--situation_teacher_forcing 0` を指定してください。

学習開始前に、各DBの登録区間数、datasetごとの採用・学習・検証件数、Tフレーム、augmentationの有効／無効を表示します。集中度モデルとシチュエーション分類モデルの各学習段階で表示します。1件は「1人の1時間区間」であり、画像1枚ではありません。

現行方式は読み込み時のランダム変換なので、augmentationによる保存データの追加は0件、1epochの件数倍率は1倍です。例えば学習区間が7,023件なら、augmentationの有効／無効にかかわらず1epochは7,023件です。20epochでは予定入力数が延べ140,460件になりますが、独立した元区間数は7,023件です。変換の種類・内容は再抽選されるため、異なる変換の総数は固定ではありません。予定件数と異常値によるスキップ後の実績は区別してください。検証データにはaugmentationを適用しません。

これらの画像・骨格 augmentation は、07_train.py の学習時に追加オプションなしで有効になります（`--augmentation standard`）。`--augmentation none` を指定すると左右反転・色変換・グレースケール化・ランダム切り抜きを無効にし、画像前処理を検証時と揃えます。集中度・シチュエーションの両モデルに適用されます。時間方向の選択は別設定のため、5秒区間全体を比較する場合は `--sample_strategy uniform` を使用してください。

augmentation は撮影条件の違いへの対応を狙う処理ですが、精度向上を保証するものではありません。効果を確認するには、学習に使っていない右側撮影の動画や、明るさの異なる教室の動画で評価し、条件ごとの予測誤差を比較する必要があります。本説明文は現行実装の内容を記録したもので、augmentation の効果を測定した実験結果ではありません。
